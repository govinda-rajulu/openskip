## Evidence and diagnosis

Distinguish source inspection, synthetic/mock tests, actual CI builds, publication, independent provenance and device evidence. Cumulative test totals are not additive across iterations or percentages of coverage. Tests from the same author can share assumptions. Lead with what was exercised and its limits.



A nonpublishing repair does not require a release to count as merged/tested. Publication claims require real assets; phone claims require device evidence. Respect owner-deferred tests without blocking unrelated engineering. Generator consistency is not semantic correctness. No-op edits, repeated summaries and commit messages are not proof of actual values.



Read the active implementation and its downstream consumer. Prove inputs nonempty and coverage nonzero. A green job may have skipped useful work. Filename suffixes and host metadata digests do not prove authenticity/runtime safety. Time-to-failure is a clue, not a causal diagnosis. After unsupported theories, inspect raw evidence rather than invent another story.



Match run/head/ref/target; rerun tests its original commit. Bound polling and batch reads. gh run watch shows status, gh run view --log-failed reads identified failure logs; do not assume API redirects return ZIPs. Copy grep strings from actual source and preserve full output when filters hide failures. Public endpoints may be stale/truncated: check commit/tree relationships and completeness. The sandbox has no internet access; separate public fetch tools from owner-side authenticated execution.



YAML parsing is not actionlint, actionlint is not runtime permission validation. Disclose unavailable tools. Read exact CLI subcommand/version and argument grouping before automating; a helper can overwrite a value, and a first glob can choose stale bytes. Never print secret-bearing argv.
