## Executive summary
Nothing drifted in the code: nothing changed for 24 days, and the repo has no package.json or tests. The mess comes from three sources:
1. Refactors dropped behaviour, and nothing caught it:
   - 69ad02c deleted the prefs cloud push.
   - The pushState hook never worked from the isolated world.

The user-facing top 5 are C2, B1, C1, C6 and S1.

## content-scripts/content.js
- **C1 (high).** Alt+Right (1843) calls isInSegment, which is scoped inside findActiveSegment (824). It throws a ReferenceError, so the manual skip never works. Fix: use findActiveSegment(segments, t).segment.
- **C2 (high).** When the URL changes, checkSkipSegments (1775) sets segments=null but leaves resolved=true. resolveSegments (1737) therefore returns early forever, and skipping dies after the first video on a reused <video> (YouTube next, next episode).
  - Related: checkUrlChange uses one module-level _lastHref (12) shared by all videos.
  - _promptedVideos (21, 550) blocks resume for the next episode on the same element.
  - Fix: per-video href, reset resolved, a generation token so stale fetches are dropped, and re-run resume keyed by mediaId.
- **C3.** The history.pushState/replaceState wrap (1906) runs in the content-script world, so it never sees page calls. Only popstate and timeupdate polling detect navigation.
- **C4.** The top-frame relay (1330) accepts labels matching /^[\w .+-]{1,40}$/, but every real label starts with ⏭ (841) and may end ★/◆. The relay is dead, so the iframe draws its own button. It also does not check that e.source is a child frame. Fix: an allowlist built from SEGMENT_LABELS, plus a badge.
- **C5.** The still-watching poller (1019, every 3 s) runs in every frame on every site. It ignores skipEnabled and site-off rules, and its fallback clicks the first button inside any [class*=overlay|modal|dialog].
- **C6 (high).** getSitePrefs (163) has four defects:
  - rules starts null, so the first call ignores the rule, and 549 gates all skipping on it.
  - ts is stamped before the read, and the catch is silent.
  - It polls every 5 s in every frame.
  - It uses location.hostname, not _siteHost(), so on aggregator sites the player iframe never matches the user's rule.
  - Separately, a rule saved as www.x.com (options 677 does not strip www) never matches.
- **C7.** The iframe init waits only 5 s for a <video> (2000-2010). Players that create the video on click never attach.
- **C8.** The countdown's pause listener is never removed, so onDone can fire twice.
- **C9.** Stats use racy read-modify-write (recordSkipStat 856, sessionsTotal++ 1725). If the key is missing, the result is NaN.
- **C10.** The cloud-to-local pull writes url: row.media_id (1975) instead of row.page_url, so links in history break.
- **C11.** subtitle_override_srt is global. One uploaded .srt applies to every video and site until it is cleared.
- **C12.** 5 console.warn calls (419, 813, 1570, 1749, 1759). The 813 branch is dead code: background never returns not_configured for FETCH_SEGMENTS.
- **C13.** Leaks:
  - Segment retry timers are never cancelled.
  - ensureSubOverlay adds fullscreen listeners and a ResizeObserver each time it is recreated.
  - One keydown listener is added per video (1834) and never removed.
- **C14.** SKIP_SELECTORS (1029) is dead code.

## background.js
- **B1 (high).** providerIntroDB returns null when there is no introdbApiKey (322), but IntroDB reads are public (their docs say so; see also this code's comments at 320 and options 207). Keyless users get no IntroDB skipping. options verifyIntrodb marks keyless as an error, and movies are unsupported. **OWNER DECISION:** removing the gate sends IMDb IDs to IntroDB without any setup, which PRIVACY.md must then disclose.
- **B2.** On Firefox (IS_SW false, 31 and 569) the queue-flush and cleanup alarms are never created. The offline queue only flushes on install/update or the online event, and cleanupOldData effectively never runs. Bodies that failed with 4xx stay queued forever.
- **B3.** TMDB auth is split:
  - TMDB_TO_IMDB and options verifyTmdb send Bearer (a v4 token).
  - TMDB_SEARCH_POSTER sends api_key= (a v3 key).
  - Whichever key type you have, one of the two features fails.
- **B4.** The TMDB cache stores null forever with no TTL when the key is missing or the request fails (634, 643, 822, 853). Adding a key later never repairs those entries. TMDB_TO_IMDB also skips the r.ok check.
- **B5.** SUPABASE_GET and GET_ALL skip r.ok. A PostgREST error object is treated as a row, which writes NaN into the cache.
- **B6.** cleanupOldData uses a bare fetch with no res.ok check. The OSUB_UA fallback is '1.8.0'.

## options.js / popup.js
- **O1 (high).** Every settings write calls ss_put_settings with p_stats {}, p_prefs {} and p_theme null (bg 738-744), and the SQL on conflict overwrites all columns. Since 69ad02c removed the prefs push (see 69ad02c^:options.js 499-519), the only writers are site-rule add/delete (655, 686), so cloud prefs, stats and theme are always wiped.
  - The pull at 516 writes cloud prefs unfiltered into local storage. No allowlist exists, and DENY keys such as supabaseUrl could arrive this way.
- **O2 (high).** Sync Now pushes the whole local cache through ss_put_playback. That sets updated_at=now() with device 'SkipStream Options Sync', which overwrites newer progress from other devices.
- **O3.** Import replaces skipstream_stats without skipsBySite or timeSavedToday, and re-importing double-counts.
- **O4.** Cloud prefs are applied only when local has no skipMode.
- **P1.** Popup segment toggles write skipMode without skipEnabled.
- **P2.** The popup file input is broken in Firefox (job 2.4). Its extension check is by name only.

## supabase_setup.sql
- **S1 (high).** playback_states has anon policies using(true) for select, insert, update and delete (51-66), plus grant all to anon (133). Anyone holding the public anon key can read, modify or delete every user's rows through REST.
  - All client traffic already goes through RPCs (grep: zero direct /rest/v1/playback_states), so revoking is safe for the code.
  - But supabase-validate.yml REQUIRES those 4 policies, so CI currently blocks the security fix.
  - The owner must re-run the SQL in Supabase.
- **S2.** ss_put_playback always overwrites and stamps now(). There is no "newer wins" guard, which is the root cause behind O2.
